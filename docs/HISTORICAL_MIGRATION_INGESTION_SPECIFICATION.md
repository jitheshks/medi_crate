# MediCrate — Historical MySQL Dump Ingestion Specification (Phase 8.2.2)

> **Document Version:** 1.0.0  
> **Target Audience:** Engineering, Database Administrators, DevOps  
> **Status:** Parser & Pipeline Ready for Historical Ingestion  

---

## 1. Overview & Operational Principles

MediCrate provides a local, repeatable, non-destructive ETL preparation pipeline for importing historical MediVault MySQL data into MediCrate PostgreSQL/Supabase.

### Safety Guarantees
* **Strictly Non-Destructive:** The source dump file and source attachment directory are accessed **read-only**. The pipeline never modifies, overwrites, or truncates any legacy source data.
* **Deterministic RFC 4122 v5 UUID Generation:** Legacy integer primary keys are deterministically mapped to UUIDs using namespace isolation tied to `sourceDatabaseId`.
* **Zero Production Secret Exposure:** Password hashes, salt strings, and credentials are never included in reconciliation reports or JSON logs.
* **Strict Source Conservation Identity:**
  $$\text{source\_count} = \text{migrated\_source\_count} + \text{preserved\_separately\_count} + \text{skipped\_count} + \text{unresolved\_count} + \text{explicitly\_excluded\_count}$$

## 2. Migration CLI Usage & Input Options

The migration runner is executed via the Dart CLI tool:

```bash
dart run tool/prepare_migration.dart [options]
```

### Command-Line Arguments Reference

| Option | Required? | Default | Description |
| :--- | :---: | :---: | :--- |
| `--input=<path>` | **Yes** (in production) | *None* | Path to uncompressed MySQL SQL dump (`.sql`) or structured JSON dump (`.json`). |
| `--source-db-id=<id>` | **Yes** (with `--production` or real dump) | *None* | Unique tenant/instance identifier (e.g. `medivault_prod_01`) to isolate UUID namespaces. |
| `--source-storage-dir=<path>` | Recommended | *None* | Path to legacy storage root containing attachments. |
| `--output-dir=<path>` | Optional | `supabase/.temp/migration_output` | Destination directory for generated artifacts and reports. |
| `--production` / `--prod` | Optional | `false` | Enforces production safety gates: forbids sample datasets and mandates explicit `--source-db-id`. |
| `--sample` | Optional | `false` | Explicit flag to execute reference sample dry run for development tests. |
| `--help` / `-h` | Optional | - | Prints complete usage instructions and exits. |

## 3. Expected Source Dump Format

The dump parser requires an **uncompressed plain-text SQL file** (`.sql`) generated by `mysqldump` or Laravel database backup utilities.

### Recommended `mysqldump` Command
To extract a consistent, compatible MySQL export from the MediVault server:

```bash
mysqldump \
  --host=<mysql_host> \
  --port=3306 \
  --user=<mysql_user> \
  -p \
  --default-character-set=utf8mb4 \
  --single-transaction \
  --quick \
  --skip-lock-tables \
  --complete-insert \
  --extended-insert \
  <medivault_database_name> > medivault_dump.sql
```

### Supported SQL Constructs
* Character Set Introducers: `_utf8mb4'...'`, `_binary'...'`, `N'...'`
* Escape Sequences: `\'`, `\"`, `\\`, `\0`, `\n`, `\r`, `\t`, `\Z`, `''`, `""`
* Literals: Bit literals (`b'1'`, `b'0'`), Hex literals (`0x416c...`, `X'416c...'`)
* Statements: `CREATE TABLE`, `INSERT INTO`, `INSERT IGNORE INTO`, `REPLACE INTO`
* Versioned Comments: `/*!40101 ... */`, `/*!40000 ... */`

### Strictly Unsupported Constructs (Fail-Fast)
* Compressed files (`.gz`, `.zip`, `.bz2`, `.xz`, `.7z`, `.tar`) — must be decompressed before execution.
* Data-modifying statements (`UPDATE`, `DELETE`, `MERGE`, `TRUNCATE`).
* Bulk ingestion directives (`LOAD DATA INFILE`, `INSERT ... SELECT`).

## 4. Expected Attachment Directory Structure

When `--source-storage-dir` is provided, the tool performs physical disk validation (existence, file size limits, MIME whitelist, and SHA-256 checksum generation).

The directory structure corresponds to Laravel's `storage/app/public/` layout:

```
<source_storage_dir>/
├── uploads/
│   ├── avatars/
│   │   ├── user_101.jpg
│   │   └── user_102.png
│   ├── consultations/
│   │   ├── con_501_slip.pdf
│   │   └── con_502_rx.png
│   ├── reports/
│   │   ├── rep_901_lipid.pdf
│   │   └── rep_902_xray.jpg
│   └── receipts/
│       └── rec_2001.jpg
```

### Bucket Routing & Validation Policies

| Legacy Category | Storage Bucket | Target Path Pattern | Max File Size | Permitted MIME Types |
| :--- | :--- | :--- | :---: | :--- |
| **Profile Avatars** | `avatars` (private) | `{user_id}/{profile_id}.{ext}` | 5 MB | `image/jpeg`, `image/png`, `image/webp` |
| **Consultation Files**| `consultations` (private) | `{user_id}/{consultation_id}/{filename}`| 25 MB | `application/pdf`, `image/jpeg`, `image/png`, `image/webp` |
| **Lab/Diagnostic Reports**| `reports` (private) | `{user_id}/{report_id}/{filename}` | 25 MB | `application/pdf`, `image/jpeg`, `image/png`, `image/webp` |

## 5. Production Execution Command

Once the actual MySQL dump (`medivault_dump.sql`) and attachments directory are mounted locally:

```bash
dart run tool/prepare_migration.dart \
  --input=/path/to/medivault_dump.sql \
  --source-db-id=medivault_prod_01 \
  --source-storage-dir=/path/to/medivault_storage/app/public \
  --production
```
